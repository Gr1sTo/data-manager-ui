# Data Manager UI

## Опис програми

**Тема магістерської роботи:**  
«Графічний інтерфейс користувача підсистеми керування сховищем даних програмного комплексу SmartEnergy».

**Data Manager UI** — вебінтерфейс для роботи з даними програмного комплексу SmartEnergy. Програма розроблена на React та призначена для взаємодії користувача з різними типами даних через REST API.

Передбачено три режими роботи:

- реляційні дані;
- документоорієнтовані дані;
- файлові дані.

Інтерфейс забезпечує перегляд даних, пошук, сортування, пагінацію, додавання, редагування та видалення записів.

Для розробки й тестування використовується демонстраційний REST API (`mock-api`).

---

## Необхідне програмне забезпечення

Для локального запуску проєкту необхідні:

- Windows 10/11 або Linux;
- Node.js;
- npm;
- Git;
- Docker / Docker Desktop — для запуску Demo API у контейнері;
- сучасний веббраузер.

Окрема СУБД для демонстраційної версії не потрібна. Тестові дані зберігаються у JSON-файлах.

## Встановлення та запуск

### 1. Клонування репозиторію

```bash
git clone <URL-репозиторію>
cd data-manager-ui
```

### 2. Встановлення залежностей

```bash
npm install
```

### 3. Налаштування API

Адреси API задаються у файлі `.env`:

```env
VITE_RELATIONAL_API_URL=http://localhost:6023/api/relational
VITE_DOCUMENT_API_URL=http://localhost:6023/api/document
VITE_FILE_API_URL=http://localhost:6023/api/file
```

Для підключення інших API необхідно змінити відповідні адреси у змінних середовища в `.env`. Ці змінні використовуються у файлі `src/api/config.js`.

Після зміни `.env` необхідно перезапустити застосунок.

### 4. Запуск Demo API

Demo API можна запустити локально командою:

```bash
node mock-api/demo-server.js
```

Сервер запускається на порту `6023`.

Також Demo API можна запустити через Docker.

Створення образу:

```bash
docker build -f mock-api/Dockerfile -t gr1sto/data-manager-ryzhenko-demo:latest .
```

Запуск контейнера:

```bash
docker run -p 6023:6023 gr1sto/data-manager-ryzhenko-demo:latest
```

### 5. Запуск графічного інтерфейсу

В окремому терміналі виконати:

```bash
npm run dev
```

Після запуску відкрити у браузері адресу, вказану в терміналі.

# Інструкція користувача

## Вибір типу даних

У верхній частині інтерфейсу розташований список вибору типу даних.

Користувач може перемикатися між режимами:

- «Реляційні дані»;
- «Документоорієнтовані дані»;
- «Файлові дані».

Після вибору режиму область відображення даних автоматично оновлюється.

## Робота з реляційними даними

Після вибору режиму **«Реляційні дані»** відображається перелік доступних таблиць.

Для перегляду вмісту необхідно вибрати потрібну таблицю та натиснути **«Відкрити»**. Після цього відображаються записи таблиці та доступні операції роботи з ними.

## Пошук

Для пошуку необхідно ввести значення у поле пошуку. Інтерфейс відобразить записи, які відповідають введеному запиту.

## Сортування

Для сортування необхідно натиснути на заголовок відповідного стовпця.

Перше натискання виконує сортування за зростанням, повторне — за спаданням.

## Перегляд запису

Кнопка **«Переглянути»** відкриває модальне вікно з повною інформацією про вибраний запис.

## Додавання запису

Для створення нового запису необхідно:

1. Відкрити потрібну таблицю.
2. Натиснути **«Додати»**.
3. Заповнити необхідні поля.
4. За потреби додати власні поля.
5. Підтвердити створення запису.

Після успішного додавання новий запис відображається у таблиці.

## Редагування запису

Для зміни даних необхідно натиснути **«Редагувати»** біля потрібного запису, внести необхідні зміни та зберегти їх.

## Видалення запису

Для видалення необхідно натиснути **«Видалити»** біля відповідного запису та підтвердити операцію у модальному вікні.

## Пагінація

Якщо кількість записів перевищує кількість елементів на одній сторінці, для переходу між сторінками використовуються кнопки **«Назад»** та **«Далі»**.

## Примітка

Demo API використовується для локальної розробки, тестування та демонстрації можливостей графічного інтерфейсу.

У програмному комплексі SmartEnergy передбачається взаємодія графічного інтерфейсу з окремими API підсистем зберігання реляційних, документоорієнтованих та файлових даних.
